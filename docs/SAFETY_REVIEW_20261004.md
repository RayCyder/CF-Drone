# 飞行停机安全复核（2026-10-04）

## 范围

本轮聚焦解锁后的终止路径：遥控失联、迫降、倒置、主循环阻塞、Web 急停和调试电机试转。开机自检仅检查它不能在主循环阻塞时持续输出。

## 发现与修复

1. **迫降没有终止条件**：旧逻辑可长期保持约 42% 目标推力。现在迫降最长 8 秒，到期由独立任务直接写零电机 PWM，再由恢复的主循环同步上锁状态。
2. **倒置保护太慢且依赖主循环**：持续倒置截止从 1.5 秒改为 0.5 秒；首次识别倒置后，截止时限由独立任务执行。
3. **主循环冻结会保留上次非零 PWM**：电机输出每次刷新都写心跳。解锁且有非零输出时，若 250 ms 未刷新，核0高优先级安全任务直接将四路写零。这同时覆盖实体 RC 失联未来得及被主循环处理的情况。
4. **Web 失联的最终停机依赖主循环**：独立任务直接监视 Web 最后更新时间，失联与迫降总时限到期后强制停机。通常情况会先被 250 ms 输出心跳保护截断。
5. **独立截止原因丢失**：紧急截止锁存迫降超时、倒置、Web 失联、主循环停顿或 Web 急停原因。主循环恢复后写入 `HARD_STOP` 系统事件并保留上锁原因。
6. **安全任务创建失败仍可解锁**：独立飞行停机任务或 Web 快速停机任务未就绪时，解锁检查直接拒绝解锁。
7. **调试电机试转依赖主循环计时**：使用 `esp_timer` 独立一次性定时器写零；定时器创建或启动失败时拒绝试转。
8. **ESP32-D 内部 DRAM 链接溢出**：控制台历史从 46 行减为 44 行，回收 480 B 静态内存，固件重新链接通过。

## 验证

- 主机回归：`python3 tests/run_host_tests.py` 通过。
- 启动电机自检顺序和独立截止契约：`python3 tests/test_boot_motor_self_check_order.py` 通过。
- Web 调试控制台与遥测页面回归通过。
- ESP32-D `min_spiffs`：Flash 1,390,311 B，静态 RAM 124,116 B，通过。
- XIAO ESP32-S3 `default_8MB`：Flash 1,349,663 B，静态 RAM 123,424 B，通过。

## 仍需实机验证的边界

- 8 秒迫降上限不是触地检测。从较高高度失联时，可能在触地前停机。
- 250 ms 主循环停顿阈值将故障时的持续推力时间设为上限。若真实飞行中出现接近该值的合法调度停顿，固件会安全停机，需要先排除停顿根因，不应通过放宽阈值掩盖。
- 倒置保护仍需主循环至少成功识别一次倒置；一旦识别，后续 0.5 秒截止不再依赖主循环。若主循环先冻结，250 ms 输出心跳保护会先停机。
