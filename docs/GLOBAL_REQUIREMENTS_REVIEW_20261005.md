## 2. 跨模块不变量

1. 一个控制输出拥有者；停止/接管后不恢复陈旧序列、AUTO 或杆量。设备状态为准，浏览器标志不得代替它。
2. 硬停机锁存与操作员上锁高于全部输出路径；应急请求不受普通页面过滤/队列/lease 过期限制，仍校验有效 stop 凭证。
3. 解锁门槛由设备判定；状态未知不乐观解锁。HTTP 已收到/入队与主循环已经执行分别表示。
4. 输入/传感器/快照检查新鲜度；网络恢复不意味着恢复旧指令；页面后台不得用陈旧非零杆量续期。
5. 参数跨入口共享校验、持久化和重启门槛；失败或断电保持可解释状态。
6. 请求失败、动作失败和能力不可用可见。主机、浏览器、台架、飞行四层证据不互相替代。

## 4. 需求与验收缺口

- **完整预检出口**：`diagnostics.ino:642` 的 `diag brief` 不含 `control.ino:422` 的完整阻断原因。统一 `arm_ready/arm_reason`，并涵盖 requestArm 最终停机锁存/并发检查；几个正常值不等于可起飞。R10。
- **下降测点来源**：控制页 `:860` 的 localStorage 点包含时间、电压、倾角，缺少设备、镜像及机体/桨叶配置。明确跨设备复用与过期规则。保存合法历史点不要求当前采集 usable，不能将缺少当前 summary 误报为缺陷。R12。
- **能力边界**：无磁力计校准的策略已闭合；电机检测仅能证明扰动，气压仅作有界单侧保护。自动学习悬停推力/定高/触地/位置悬停仍为未实现需求，不列为现有算法 bug。R06/R07/R12/R13。
- **旧台架前提**：`ESP32D_ACCEPTANCE_TEST_PLAN.md` 仍称气压计没有驱动，且默认上电无试转。基线已有 BMP388 驱动和开机电机自检；执行前按实际板型与构建开关修订，不复用旧设备/桨叶状态。R04/R14。
- **页面生命周期**：基线仅处理 pointerup/pointercancel，没有 visibilitychange/pagehide/blur。切后台后动画发送可能停止、心跳仍运行，最后杆量可保留到摇杆失联截止；不同浏览器的后台定时器行为不同。定义失焦后的杆量、回位、续期与恢复手势规则，避免自动恢复陈旧偏转；用真机后台/锁屏验证，不以模拟时钟代替。R02/R11。
- **MAVLink 接管回归契约**：`control.ino:240` 明确允许迫降期间接收手动输入并经持续门槛接管，`tests/test_control_state.cpp:422` 仍期望拒绝。按 R12 固定允许输入、未达到门槛不退出下降的规则，补完整持续/释放/来源仲裁回归。此处为静态确认的实现/测试冲突，本文没有自行运行测试或认定新模式安全。
- **Wi-Fi 重启与解锁互锁**：`wifi.ino:697` 排队 1.5 秒后重启，`:558` 仅在消费时检查 armed/motors；`armBlockReason()` 没有“重启已排队”原因。定义全局互锁与原子执行边界，覆盖保存后立即申请解锁、重启判断与解锁并发、延迟至上锁后重启的情况。R03/R10。
- **默认资源与传感器能力**：S3 禁用 BMP/QMC 时，外设 setup 直接跳过初始化，不能仅因 EXPANSION_BOARD_ENABLED 就宣称其它外设已探测；C3 默认关闭 Wi-Fi/Web。构建开关与运行能力表分别记录。R08/R14。
