# 迫降过快反馈：板端数据判读

目标设备 MAC `20:50:0d:33:58:40`。操作者报告“迫降下降太快”。读取时设备已上锁，电压约 `3.92 V`、故障位 0。读取到的 `SF_DESCEND_THRUST=0.350`，参数已保存；代码中 `descendTime=3 s`，迫降采用固定目标推力和渐变过渡，没有高度或垂直速度闭环，因此不能保证下降速度。

导出的 generation 3 冻结日志是板端时间 `1574.713–1578.753 s`，共 400 行、漏采 13 行；CSV SHA-256 `599040a0f578d2fd511575c6b576e6781dc315b7b364686e9bb7d6b5399cfcfa`。原因码 `0x81000000` 是 Web 上锁触发。全段 `flight_mode=STAB (2)`、`control_source=WEB_RC (2)`，未进入迫降源 `LANDING (6)`。其中约 `1575.602 s` 手动油门降为零，约 `1577.763 s` 上锁；因此这些行不能用来计算用户所述迫降的推力轨迹或下降速度。

另从实时遥测端口读取到板端保留的事件：`1763.352 s` Web 模式切换至 AUTO，`1763.381 s` 收到 `Btn=0x0008` 迫降按钮，`1763.506 s` 低电告警激活，`1764.155 s` 低电告警解除，`1769.741 s` Web 上锁。迫降事件比冻结快照晚约 185 秒；旧快照未恢复滚动采样，故实际迫降阶段无 100 Hz 日志。事件只确认按钮输入和告警时序，未提供实时推力、电压、垂直速度或高度。

结论：可以确认迫降被请求、参数为 `0.350`，但无法根据现有记录量化下降速度，也不能证明是低推力、低压还是其他因素导致下降过快。若要调整目标推力，需在受控条件下记录有效手动下降段及实测高度差，用现有“迫降推力标定”流程得到候选值；不要仅凭本次缺失数据推算或直接写入更高推力。下一次前应先恢复机载日志滚动采样，并持续保存迫降期间的遥测；冻结窗口只有约 4 秒，事后过久或被较早事件冻结均会丢失关键阶段。
